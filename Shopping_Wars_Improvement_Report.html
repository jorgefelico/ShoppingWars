📋 Executive Summary

Shopping Wars is a well-architected 4-player multiplayer battle royale game built with Godot 4.7 and C#. The project demonstrates solid understanding of multiplayer networking, Steam integration, and game loop management. However, several areas require attention for production readiness, performance optimization, and maintainability.

✅ Strengths

  • Excellent Steam P2P Relay integration with proper lobby management
  • Well-structured game phases (Lobby → Shopping → Battle Royale)
  • Network interpolation for smooth remote player movement
  • Server-authoritative design for critical game logic
  • Clean separation of concerns with interfaces (IDamageable, IInteractable)
  • Effective inventory and hotbar system

⚠️ Critical Concerns

  • High-frequency state synchronization causes excessive RPC calls
  • No input lag compensation for throwing mechanics
  • Limited error handling and edge case coverage
  • Memory management issues with remote player cleanup
  • Insufficient anti-cheat measures

🚀 1. Performance & Optimization

1.1 Excessive State Synchronization

// GameManager.cs:18 - Current sync interval private const float SyncInterval = 0.25f; // 4 times per second

⚠️ Issue: Syncing state every 250ms is too frequent for a simple game state (phase + timer). This generates 4 RPC calls per second per player unnecessarily.

Recommendation:

Reduce to 0.5s (2Hz) or implement delta-based sync:

// Option 1: Increase interval
private const float SyncInterval = 0.5f;

// Option 2: Sync only on phase change or timer milestones
if (timeRemaining % 5.0f < 1.0f) {
    // Sync every 5 seconds, not every frame
}

1.2 Hover Label Performance

// Product.cs:39-40 HoverLabel = Utils.CreateHoverLabel(HoverText); AddChild(HoverLabel);

⚠️ Issue: Creating a Label3D for every product (2 per player + Groomba = 15+ label3Ds per scene) causes:

  • Unnecessary draw calls for non-hovered labels
  • Memory overhead for Label3D instances
  • Sorting and depth testing for mostly-hidden labels

Recommendation:

Pool and reuse hover labels:

// Create a shared pool of hover labels
private static readonly Godot.Collections.Array<Label3D> _hoverPool = new Godot.Collections.Array<Label3D>();

public static Label3D GetHoverLabel(Node3D parent)
{
    if (_hoverPool.Count > 0)
    {
        var label = (Label3D)_hoverPool.Back();
        _hoverPool.RemoveBack();
        label.Visible = true;
        label.Reparent(parent);
        return label;
    }
    return Utils.CreateHoverLabel("Hover");
}

1.3 Physics Performance

// Product.cs:62-74 public override void _PhysicsProcess(double delta) { MoveAndSlide(); if (BodyEntered != null) { foreach (var body in GetTree().PhysicsDirectSpaceState3D.AllCollisionObjects) { if (body is IDamageable damageable) { if (damageable != Thrower) { damageable.TakeDamage(Damage); } } } } }

⚠️ Issue: AllCollisionObjects query runs every physics frame (60 times/sec) for every thrown product. With 5 products thrown simultaneously, that's 300 physics queries per second!

Recommendation:

Use BodyEntered signal instead:

// During _Ready()
BodyEntered += OnBodyEntered;

// During _PhysicsProcess()
MoveAndSlide();
// Don't query space state here!

// In OnBodyEntered callback
public void OnBodyEntered(Node body)
{
    if (body is IDamageable damageable && damageable != Thrower)
    {
        damageable.TakeDamage(Damage);
    }
}

🌐 2. Network & Multiplayer Issues

2.1 Client-Side Damage Calculation

// Health.cs:31-36 public void TakeDamage(int amount) { if(!Multiplayer.IsServer()) return; CurrentHealth = Mathf.Clamp(CurrentHealth - amount, 0, MaxHealth); if (CurrentHealth == 0) IsDead = true; Rpc(nameof(RpcSyncHealth), CurrentHealth, IsDead); }

⚠️ Issue: The PlayerController implements IDamageable, but Health.TakeDamage only executes on server. However, Product.cs performs the damage check client-side too!

// Product.cs (client-side logic)
if (damageable != Thrower)
{
    damageable.TakeDamage(Damage);
}

This creates a desync vulnerability. A client can modify Thrower to avoid taking damage.

Recommendation:

Make damage fully server-authoritative:

// On server (in GameManager or dedicated damage handler)
[Rpc(MultiplayerApi.RpcMode.AnyPeer)]
public void RpcApplyDamage(Node3D victim, int damage, Node3D thrower)
{
    var victimPlayer = victim as PlayerController;
    if (victimPlayer != null)
    {
        victimPlayer.TakeDamage(damage);
    }
}

2.2 No Cheat Detection

⚠️ Issue: No validation for:

  • Velocity manipulation: Players can edit linear_velocity to throw products faster
  • Position teleportation: Clients can set GlobalPosition freely
  • Health manipulation: Health can be set to max client-side
  • Inventory manipulation: Items can be added/removed client-side

Recommendation:

Implement server-side validation:

public void SyncPosition(Vector3 position)
{
    // Validate position is within bounds
    Vector3 bounds = new Vector3(40, 0, 40);
    if (position.X < -bounds.X || position.X > bounds.X || 
        position.Z < -bounds.Z || position.Z > bounds.Z)
    {
        GD.PrintErr("Invalid position attempt detected!");
        return;
    }
    
    // Validate velocity is reasonable
    if (position.DistanceTo(PreviousPosition) > 10.0f)
    {
        GD.PrintErr("Excessive movement detected!");
        return;
    }
}

2.3 Missing Reconnect Logic

// NetworkManager.cs:44-47 private void OnConnectionFailed() { GD.PrintErr("[NetworkManager] Connection Failed to Host!"); }

⚠️ Issue: Connection failure only prints an error. No user feedback, no retry logic, no fallback to solo mode.

Recommendation:

Add proper error handling:

private void OnConnectionFailed()
{
    GD.PrintErr("[NetworkManager] Connection Failed!");
    
    // Show error dialog to user
    var dialog = GD.Load<PackedScene>("res://UI/ConnectionError.tscn").Instantiate();
    dialog.ShowDialog();
    
    // Auto-quit after delay
    GetTree().CreateTimer(5.0).TimerTimeout += () => GetTree().Quit();
}

🏗️ 3. Code Quality & Architecture

3.1 Magic Numbers

// PlayerController.cs:127-128 float lerpFactor = 1.0f - Mathf.Exp(-22.0f * (float)delta);

⚠️ Issue: Magic number 22.0f for lerp factor makes the interpolation strength hard to tune.

Recommendation:

Use named constants:

const float NetworkLerpFactor = 22.0f; // Higher = faster correction
float lerpFactor = 1.0f - Mathf.Exp(-NetworkLerpFactor * (float)delta);

3.2 Inconsistent Null Checks

// PlayerController.cs:53-64 if (IsMultiplayerAuthority()) { // ... if (Camera != null) { Camera.MakeCurrent(); GD.Print($"[PlayerController] Activated Camera for Local Authority Player '{Name}'"); } }

⚠️ Issue: Null checks scattered throughout code. Some paths don't check for null before using objects.

Recommendation:

Centralize null safety:

private void InitializeLocalPlayer()
{
    if (Camera == null)
    {
        Camera = GetNode<Camera3D>("Head/Camera");
    }
    Camera.MakeCurrent();
}

// IInteractable.cs:8-17 void OutlineOn() { if(Outline != null) Outline.Visible = true; if(HoverLabel != null) HoverLabel.Visible = true; } void OutlineOff() { if(Outline != null) Outline.Visible = false; if(HoverLabel != null) HoverLabel.Visible = false; }

Add default implementations that throw:

public void OutlineOff()

3.4 Memory Leaks with Remote Players

// PlayerController.cs:67-78 else { if (Camera != null) Camera.Current = false; // Delete UI elements on remote player clones foreach (Node child in GetChildren()) { if (child is CanvasLayer canvasLayer) { canvasLayer.QueueFree(); } } }

⚠️ Issue: When a player disconnects, the server doesn't clean up remote player instances. This causes:

  • Orphaned nodes accumulating in scene tree
  • Memory leaks over time
  • Ghost players potentially visible

Recommendation:

Add proper cleanup in NetworkManager:

private void OnPeerDisconnected(long id)
{
    GD.Print($"[NetworkManager] Peer Disconnected: {id}");
    
    // Find and remove player with this ID
    foreach (Node node in GetTree().GetAllNodes())
    {
        if (node is PlayerController player && player.Name == id.ToString())
        {
            // Call cleanup on player first
            player.OnDisconnected();
            
            // Then remove from scene
            node.QueueFree();
        }
    }
}

🎮 4. Game Mechanics & Polish

4.1 No Projectile Prediction

// PlayerController.cs:340-341 Vector3 dir = (aimPoint - HeldItem.GlobalPosition).Normalized(); float speed = ThrowVelocity * HeldItem.ThrowMultiplier;

⚠️ Issue: No projectile prediction means thrown products appear to lag behind the aiming direction on clients with latency.

Recommendation:

Implement sub-pixel prediction:

// On server when throwing
Vector3 predictedPosition = Camera.GlobalPosition + camForward * 2.0f; // Predict 2 frames ahead
Rpc(nameof(RpcThrowItem), itemPath, (predictedPosition - HeldItem.GlobalPosition).Normalized() * speed);

// Client-side prediction
float predictionOffset = latencyEstimate * ThrowVelocity;
Vector3 predictedAim = GlobalPosition + cameraForward * predictionOffset;

4.3 No Cooldowns

⚠️ Issue: Players can spam throw buttons without cooldown, leading to unfair advantage.

Recommendation:

Add throw cooldown:

private float _throwCooldown = 0.5f; // seconds

private void HandleThrow()
{
    if (Input.IsActionJustPressed("fire") && HeldItem != null && GameManager.Instance?.CurrentPhase == GamePhase.BattleRoyale)
    {
        if (_throwCooldown <= 0.0f)
        {
            // Execute throw...
            _throwCooldown = 0.5f;
        }
    }
    
    // In _Process
    if (_throwCooldown > 0.0f)
    {
        _throwCooldown -= delta;
    }
}

4.4 No Anti-Gravity

⚠️ Issue: Thrown products can fly indefinitely in the air, potentially flying outside the arena.

Recommendation:

Apply gravity and arena bounds:

// In Product.cs _PhysicsProcess
Vector3 gravity = new Vector3(0, -9.8f, 0) * delta;
Velocity += gravity;

// Check bounds and bounce or destroy
if (Position.Y < 1.0f)
{
    Position = new Vector3(Position.X, 1.0f, Position.Z);
    Velocity = new Vector3(Velocity.X, -5f, Velocity.Z); // dampen bounce
}

🛡️ 5. Error Handling & Robustness

5.1 No Steam Initialization Check

// MainMenu.cs:68-69 if (!SteamManager.Instance.IsSteamInitialized || !SteamManager.Instance.IsOnline()) return; SteamManager.Instance.HostLobby();

⚠️ Issue: While there's a check, there's no error message if Steam fails to initialize. Game might crash silently.

Recommendation:

Add error handling:

private void OnHostPressed()
{
    if (SteamManager.Instance == null)
    {
        GD.PrintErr("SteamManager not initialized!");
        ShowErrorDialog("Steam is not available on this system.");
        return;
    }
    
    if (!SteamManager.Instance.IsSteamInitialized)
    {
        GD.PrintErr("Failed to initialize Steam!");
        ShowErrorDialog("Failed to connect to Steam. Please ensure Steam is running.");
        return;
    }
    
    if (!SteamManager.Instance.IsOnline())
    {
        GD.PrintErr("Steam is not online!");
        ShowErrorDialog("Steam is not online. Please check your connection.");
        return;
    }
    
    SteamManager.Instance.HostLobby();
}

5.2 No Div Zero Protection

// HealthBar.cs:10-12 float percent = (float)currentHealth / (float)maxHealth; float fillWidth = 300f * percent; ColorRect.CustomMaximumSize = new Vector2(Mathf.Clamp(fillWidth, 0f, 300f), 20.0f);

⚠️ Issue: If maxHealth is 0, this causes a divide by zero error.

Recommendation:

Add safety check:

float percent = maxHealth > 0 ? (float)currentHealth / (float)maxHealth : 1.0f;
ColorRect.CustomMaximumSize = new Vector2(Mathf.Clamp(300f * percent, 0f, 300f), 20.0f);

5.3 No Array Bounds Checking

// Inventory.cs:41-54 public int FreeSlots() { int count = 0; foreach (var item in InventoryItems) { if (item != null) count++; } return InventorySize - count; }

⚠️ Issue: Array indexing in AddItem and RemoveCurrentSelectedItem doesn't check bounds, causing potential index out of range exceptions.

Recommendation:

Add bounds validation:

public void AddItem(Product product)
{
    for (int i = 0; i < InventoryItems.Length; i++)
    {
        if (InventoryItems[i] == null)
        {
            InventoryItems[i] = product;
            return;
        }
    }
    GD.PrintErr("Inventory is full!");
}

🔒 8. Security & Anti-Cheat

⚠️ Issue: Clients can manipulate:

  • Health: Can set health to 100

Make all state server-authoritative:

// PlayerController.cs - Remove client-side state setters

public int Money { get; private set; } // Private setter - only server can change

public void TakeDamage(int amount)
{
    if (!IsMultiplayerAuthority()) return; // Only server can call this

# Code Structure Guide

## Script Organization
- PlayerController: Main player logic (movement, input, inventory)
- GameManager: Game state, phases, timing
- NetworkManager: Multiplayer connectivity, spawning
- SteamManager: Steam API wrapper
- Product: Throwable items with physics
- Groomba: Enemy AI
- Inventory/InventoryBar: Item management
- Health/HealthBar: Health system

## Multiplayer Pattern
- Server-authoritative: Server validates all damage, purchases, deaths
- Client-side prediction: Smooth movement with interpolation
- RPC patterns: CallLocal=true for local effects, false for remote
